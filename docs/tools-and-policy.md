# Инструменты и политика

## 1. Единая точка проверки

Все инструменты проходят через один `PolicyGate`:

```rust
pub enum Effect {
    Read,        // ничего не меняет вне процесса
    Mutate,      // меняет файлы, git, процессы — в пределах worktree
    External,    // выходит за пределы машины или необратимо
}

pub trait Tool {
    fn name(&self) -> &'static str;
    fn schema(&self) -> &'static serde_json::Value;
    fn description(&self) -> &'static str;                      // для списка инструментов в промпте
    fn idempotency(&self, args: &Args) -> Idempotency;          // Idempotent | ByContent | Unknown
    fn effect(&self, args: &Args) -> Effect;                    // может зависеть от аргументов
    fn paths(&self, args: &Args) -> Vec<PathUse>;               // что трогает вызов, для гейта
    fn expected_effect(&self, args: &Args) -> String;           // про ЭТОТ вызов, для журнала (D-081)
    fn execute(&self, ctx: &ToolCtx, args: Args) -> ToolResult;
    // probe живёт отдельно: recovery спрашивает инструмент по записи журнала, без запуска
}
```

`expected_effect` — не `description`. Описание говорит, что инструмент *такое* («Write a complete
file…»), и одинаково для всех вызовов; ожидаемый эффект называет файл, команду или вопрос —
именно его читает человек в `immortality log` и именно его цитирует recovery, когда не может
понять, подействовал ли прерванный вызов. По умолчанию строится из `paths` («write
src/parser.rs»), инструменты с эффектом в аргументе переопределяют («run `cargo test`»).
Фраза всегда одна строка не длиннее 120 символов.

`PolicyGate::check(tool, args) -> Allowed | Escalate(reason) | Denied(reason)`:

1. `Effect::Read` → разрешено, если путь внутри `workspace_root` и не попадает в
   `deny_read_globs` (D-100).
2. `Effect::Mutate` → path allowlist + `deny_write_globs` + правило «только внутри worktree».
3. `Effect::External` → в очередь эскалаций, никогда не исполняется автоматически, даже если
   в конфиге стоит `allow_* = true` (флаг лишь позволяет пометить эскалацию как
   auto-approved для конкретных хостов или типов).
4. Любая попытка выйти за `workspace_root` → `Denied` + событие в журнал (это индикатор
   промпт-инъекции или зацикливания).
5. `deny_programs` проверяется **до** пунктов 1–4 и до сокращения для `trusted_hosts`: программа
   из списка не запускается ни при каких флагах (D-100).

Пункт 2 знает одно исключение: перенаправление в устройство-приёмник (`/dev/null`, `/dev/stdout`,
`/dev/stderr`, `/dev/zero`, `/dev/full`) — не путь, и проверять его не нужно. Точное совпадение
имени, не префикс: `/dev/null.txt` и `/dev/sda` остаются путями. Эффект при этом остаётся
`Mutate`, а `echo x > /dev/null; echo y > /etc/passwd` по-прежнему отказ — приёмник пропускается,
остальные пути судятся как обычно (D-102).

`Denied` — это observation модели, а не падение: она получает «действие запрещено
политикой, причина X, разрешённые альтернативы Y».

## 2. Каталог v0.1

### Чтение (Effect::Read)

| Инструмент | Параметры | Примечания |
| --- | --- | --- |
| `read_file` | `path`, `offset`, `limit` | Нумерация строк; отказ на бинарных файлах с подсказкой |
| `glob` | `pattern`, `path` | Сортировка по mtime, лимит результатов |
| `grep` | `pattern`, `glob`, `path`, `-A/-B`, `limit` | Регексы; поиск идёт только по текстовым файлам |
| `read_state` | `file`, `offset`, `limit` | Пять документов `PLAN.md` / `ACCEPTANCE.md` / `TASKS.json` / `DECISIONS.md` / `NOTES.md` (D-065) |
| `grep_journal` | `query`, `since_seq`, `kind`, `limit` | Поиск по журналу; `next_seq` — курсор для следующей страницы (D-066) |
| `git` с `subcommand` = `status`/`diff`/`log`/`show`/`rev_parse` | `args` — массив argv | Только чтение |

### Изменение (Effect::Mutate)

| Инструмент | Параметры | Идемпотентность |
| --- | --- | --- |
| `write_file` | `path`, `content` | ByContent |
| `edit_file` | `path`, `old`, `new`, `replace_all` | ByContent |
| `git` с `subcommand` = `add`/`commit`/`branch`/`worktree`/`stash` | `args`, `message`, `path`, `reason` | commit → Unknown (probe по `Immortality-Call` trailer) |
| `update_state` | `file`, `content`, `replace` | ByContent; отказ создать отсутствующий файл и урезать вдвое без `replace` (D-065) |
| `shell` (mutating) | `command`, `timeout_secs`, `cwd` | Unknown |
| `start_process` | `command`, `cwd`, `env`, `name` | Unknown (probe по маркеру в командной строке, D-061) |
| `kill_process` | `handle` | Idempotent |

`git` — один инструмент с закрытым перечислением подкоманд (D-063), а не восемь отдельных.
`push`, `fetch`, `pull`, `clone`, `remote` и `config` в перечисление не входят: человек делает
push и merge, а `.git/config` уже в built-in deny-списке. Команды выполняются в worktree
задачи, путь берётся у gate, а не из аргументов. Общие ref'ы ограничены (D-064): `branch`
умеет только листить и создавать, `stash` — только добавлять и применять; `branch -D` из
worktree задачи удаляет ветку в чекауте человека — замерено.

`edit_file` — точная замена строки, по образцу read-tool'ов: если `old` не найден или
найден неоднократно, возвращается структурированная ошибка (модель должна уточнить
контекст), а не «первое вхождение». Это заметно снижает класс ошибок «исправил не то».

### Внешнее (Effect::External)

| Инструмент | Поведение |
| --- | --- |
| `escalate` | Создать запрос человеку: `key`, `question`, `kind`, `options` (D-067) |
| любой сетевой доступ | Только через эскалацию; хосты из `trusted_hosts` разрешены без вопроса (сюда входит `llm-server`) |
| `delegate` | Суб-агент с чистым контекстом в том же worktree: `brief`, `scope`, `max_steps` (D-068) |

**Реализация (M3.9).** `delegate` объявлен `Effect::Mutate`, а не `External`: он пишет один
отчёт в каталог состояния демона и ничего не трогает вне него, а файловые, git- и
shell-вызовы субагента проходят через тот же `PolicyGate` по одному. `scope` — не
пожелание: пути отчёта, вышедшие за него, возвращаются родителю списком
`scope_violations` и предупреждением в тексте; сами изменения не откатываются — это решает
родитель. `scope` нормализуется (без `~`, абсолютных путей и `..`) и сравнивается
покомпонентно, поэтому `src` не покрывает `srcfoo`. `max_steps` по умолчанию 20, потолок 40:
бриф, которому нужно больше, — это подзадача, а не делегирование. Вложенное делегирование
запрещено: `ToolCtx::with_depth` помечает контекст субагента, и `delegate` отказывает на
любой глубине больше нуля. Отчёт — `delegations/<del_…>.json` под каталогом задачи, id
выводится из `call_id` (D-068).

### Завершение

| Инструмент | Поведение |
| --- | --- |
| `finish_subtask` | Заявляет выполнение DoD; гейты проверяются **системой**, а не моделью |
| `finish_task` | Заявляет выполнение задачи; запускаются все гейты, включая reviewer |

## 3. Terminal

- **Persistent shell на задачу**: cwd/env сохраняются между вызовами, состояние живёт в
  демоне, не в модели.
- **stdin закрыт по умолчанию.** Команда, которая ждёт ввода, получает EOF и не вешает цикл.
- **Таймаут на вызов** (дефолт 120 с, максимум задаётся конфигом). При истечении процесс
  убивается (SIGTERM → SIGKILL через 5 с), возвращается структурированный результат
  `timeout` с тем, что успело выйти.
- **Автоперевод в фон**: если вывода нет N секунд или команда помечена как долгоживущая,
  она становится tracked-процессом с `handle`, а модели возвращается
  `{"handle": "proc_7", "hint": "read_process"}`.
- **Ограничение вывода**: всё пишется в artifact, в контекст — последние 200 строк +
  сводка (код выхода, число строк, найденные ошибки/ссылки на файлы:строка).
- **Классификатор**: `read` (git status, ls, cat, grep, cargo test/check, npm run lint…),
  `mutate` (mkdir, mv, sed -i, cargo build, npm install в worktree…),
  `external` (curl, wget, ssh, scp, git push/fetch, brew, sudo, любые обращения вне localhost).
  Незнакомая команда консервативно считается `external`.

## 4. Эскалации

Очередь, которую агент видит как pending. Форма:

```json
{
  "id": "esc_01JB...",
  "key": "network:example.com:fetch-docs",
  "task": "tsk_01JB...",
  "kind": "external_action" | "blocked" | "backend_unavailable" | "journal_corrupt" | "disk",
  "question": "Разрешить загрузку …?",
  "options": ["allow_once", "allow_for_task", "deny"],
  "blocking": false,
  "created_at": "...",
  "resolved_at": null,
  "answer": null
}
```

Правила:

- `blocking: false` (по умолчанию) — агент продолжает работу по другим подзадачам.
- Дедуп по `key`: одинаковый вопрос не задаётся дважды.
- Ответ человека — событие в журнал; `allow_for_task` живёт до конца задачи, не дольше.
- Эскалация — не конец прогона. Человек может ответить из `immortality escalations`
  в любой момент, даже посреди работы.
- macOS-нотификация (`osascript`) на открытие эскалации, без внешних каналов в v0.1.
- `blocking: true` используется только когда без ответа физически нельзя продолжать
  ни одну подзадачу (например, `journal_corrupt`).

**Реализация (M3.8).** `blocking` — не аргумент модели: он выводится из `kind`, и только
`journal_corrupt` даёт `true` (D-067). Очередь — `escalations.json` в каталоге состояния
задачи, пишется атомарно; журнал получает `escalation_opened` / `escalation_resolved`.
Повторный `escalate` с тем же `key` возвращает текущее состояние: если вопрос уже отвечен,
модель видит ответ в том же шаге и может действовать. `key` нормализуется (trim) и
ограничен 200 байтами — `external:push` и `external:push ` не должны быть разными вопросами.
Нотификация — фиксированный `on run argv`-скрипт `osascript`, текст передаётся аргументами
(не подставляется в скрипт) и ограничена по времени; отсутствие `osascript` или таймаут
не влияют на запись эскалации.

## 5. Гейты DoD

Завершение проверяет система по `ACCEPTANCE.md`:

1. **Команды проверки** (сборка, тесты, линт) — исполняются, результат в журнал
   (`gate_result`). Красный гейт = подзадача не закрыта.
2. **Reviewer-субагент** с чистым контекстом: получает только diff и DoD, возвращает
   вердикт `approve` / `request_changes` со списком проблем. Не может править код сам.
3. **Дифф-санити**: нет случайных бинарников, нет секретов (эвристика по паттернам
   `API_KEY=`, приватные ключи), нет изменений в `.git/config`, нет правок глобального
   конфига, нет `TODO(agent)` без причины.

Только при трёх зелёных гейтах подзадача → `done`, а задача при всех закрытых подзадачах →
`ready_for_review`. Модель не может объявить успех в обход проверок.

Порядок — **дешёвое первым**: санити, команды, reviewer. Находка санити уже проваливает заявку и
обрывает остальное; красная обязательная команда обрывает оставшиеся команды и reviewer;
необязательная (`required: false`) не останавливает ничего. Отказ политики и таймаут — красная
проверка: «не запускалось» и «не доказано» не бывают зелёными. Reviewer получает только
`Dod.statement` и дифф, без инструментов; любой ответ, кроме явного `approve`, — `request_changes`,
включая прозу, неизвестный вердикт, пустоту и недоступный бэкенд. Дифф — против `HEAD` (или явной
базы) плюс untracked-файлы; слишком большой дифф — находка, а не усечение.

Раннер пишет по записи `gate_result` на гейт и закрывает **попытку**; `done` в `TASKS.json`
пишет планировщик (D-079).
