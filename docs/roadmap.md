# План работ и критерии готовности

Каждая веха заканчивается работающим состоянием и тестами. Порядок выбран так, чтобы
самые дорогие ошибки (состояние, восстановление, протокол инструментов) были пойманы до
того, как появится UI и агентная петля.

## Про оценки

- Единица — **фокусированный день** одного разработчика: без встреч, переключений и ревью.
  Календарь при частичной занятости — умножать на 1.4–1.6.
- Оценка включает тесты, без которых шаг не считается сделанным.
- Оценка **не включает** отладку на живой модели: на локальных моделях это отдельный,
  плохо предсказуемый вид работы. Он вынесен в S1 и M6.
- Оценки по незнакомым API (`launchd`, `git stash create`, `portable-pty`) даны с
  запасом ~30%.

> Оценка снижена с 2.5 до 1.5 дня, освободившийся день перенесён в M2.4.

**Постоянная ценность:** `spike/src/sse.rs` (11 тестов) и `TurnAccumulator` (7 тестов)

## M1 — Домен, состояние, восстановление (14 дней)

**Сделано, когда:** симулятор убивает процесс в каждой точке протокола tool-call, и
`recover()` каждый раз приводит систему в корректное состояние.

| Шаг | Что делаем | Тесты | Дней |
| --- | --- | --- | --- |
| M1.1 | Типы домена: `Task`, `Subtask`, `Attempt`, `DoD`, `TaskState`; машина состояний с явным списком переходов | unit + `proptest`: любой путь из списка переходов валиден, вне списка — ошибка | 2 |
| M1.2 | Журнал: JSONL, атомарная запись (temp + fsync + rename), сегменты по 8 MiB, монотонный `seq`, цепочка `prev`, чтение с обрезкой битого хвоста | обрыв записи на каждом байте; разрыв цепочки; конкурентная запись из двух потоков; повторное открытие сегмента | 2.5 |
| M1.3 | Content-addressed `artifacts/`: запись по sha256, дедупликация, чтение, TTL | одинаковый payload → один файл; битый файл не возвращается молча | 1 |
| M1.4 | Протокол трёх записей (`intent`/`started`/`completed`), модель идемпотентности, trait `probe` | порядок записей; результат в журнале до выдачи модели; `probe` для всех трёх исходов | 1.5 |
| M1.5 | Чекпоинты: скрытые (временная ветка / `stash create`) и содержательные; откат `reset --hard` с предварительным `stash` незакоммиченного | откат возвращает точное дерево; незакоммиченные правки не теряются; откат к несуществующему SHA → ошибка | 1.5 |
| M1.6 | `recover()`: обрезанный хвост, разрыв цепочки, незакрытые вызовы (по идемпотентности), потерянный/чужой worktree, расхождение `attempts.json` с журналом | по одному тесту на каждый сценарий; победитель всегда журнал | 2 |
| M1.7 | `gc`: TTL артефактов, месячная архивация логов в `.gz`, защита артефактов незавершённых задач, диск-гард (1 GiB / 256 MiB) | gc не удаляет нужное; ENOSPC → `paused_disk` | 1 |
| M1.8 | Тестовый каркас: абстракция ФС, инъекция падений в произвольной точке, фейковые часы, golden-хелперы | сам каркас тестируется: внедрённый сбой действительно срабатывает | 2.5 |

**Почему M1.8 большой:** это актив, на котором держатся все остальные тесты проекта.
Без него «0 потерянных данных при `kill -9`» проверить нечем.

**Риск:** самый высокий в проекте. Атомарность + восстановление — источник тонких багов.
Правило: ни один шаг M1 не считается сделанным без теста с инъекцией сбоя.

## M2 — LLM-слой (11 дней)

**Сделано, когда:** mock-сервер отдаёт все сценарии деградации, и клиент выходит из
каждого предсказуемым состоянием.

> Факты с живого бэкенда (см. `backend-check-swift-iq2xs.md`): нативный tool-calling
> работает, аргументы в стриме приходят посимвольно, в потоке есть `: keep-alive`,
> reasoning идёт отдельным полем и отключается через `chat_template_kwargs`. Это
> сокращает объём fallback-парсера: он нужен как страховка, а не как основной путь.

| Шаг | Что делаем | Тесты | Дней |
| --- | --- | --- | --- |
| M2.1 | Типы запроса/ответа OpenAI, non-streaming путь, сериализация | serde round-trip; запрос совпадает с эталонным JSON | 1 |
| M2.2 | SSE-стриминг: дельта-ассемблинг контента и `tool_calls` по индексам, склейка частичных аргументов | ответ, разрезанный на 1-байтные чанки; два tool-call в одном ответе; пустой `delta` | 2 |
| M2.3 | Классификация ошибок (`retryable`/`fatal`), backoff 1→60 с, health-check, отмена запроса | 429/5xx/таймаут/обрыв стрима; отмена посреди стрима не оставляет висящих задач | 1.5 |
| M2.4 | Извлечение вызовов: нативный путь → fallback (```json, XML-теги, «почти-JSON» с починкой). Нативный путь подтверждён на живом бэкенде; fallback — страховка | матрица из ~20 деградаций (по данным S1); починка не «додумывает» аргументы | 1.5 |
| M2.5 | Валидация аргументов по JSON Schema, рендер ошибки для модели с ожидаемой схемой | пропущенное обязательное поле; лишнее поле; неверный тип | 1 |
| M2.6 | Учёт токенов: `usage`, эвристика как fallback, калибровка по истории | ответ без `usage`; расхождение эвристики и usage < 15% после калибровки | 0.5 |
| M2.7 | Mock-сервер в `testkit`: сценарные ответы из файла, стриминг, задержки, ошибки, «модель зациклилась» | сам mock-сервер: детерминизм, воспроизводимость, остановка без утечек | 2.5 |

**Риск:** M2.4. Fallback-парсер легко превращается в генератор ложных вызовов. Правило:
любая починка только нормализует синтаксис, но никогда не добавляет отсутствующие поля.

## Что можно резать, если сроки поехали

В порядке отказа (сверху — первое, что выбрасываем):

1. `delegate` в M3.9 (−1 д.) и `grep_journal` (−0.5 д.) — интерфейс оставить, реализацию позже.
2. `persistent shell` → процесс-на-команду (−2 д. в M3.4).
3. `AllowCommit` через модель → коммиты делает система по завершении подзадачи (−1 д. в M3.6).
4. Property-тесты машины состояний → только unit (−1 д. в M1.1, M1.8).
5. Reviewer-субагент → только команды и дифф-санити (−1 д. в M4.6).
6. Последний рубеж — **не резать**: M1.2, M1.4, M1.6, M2.2, M4.4. Это и есть ядро
   требований «не зацикливается, не теряет данные».

## Критический путь и зависимости

```
S1 ── M0 ── M1 ── M2 ── M3 ── M4 ── M5 ── M6
             │      │
             └──────┴── M1.8 и M2.7 нужны для тестов M3/M4
```

Последовательность строгая: параллелить почти нечего (один разработчик). Единственная
реальная параллельность — M0.3/M0.5 против M0.2, и M2.7 (mock) против M2.4 (парсер).

Дальше после v0.1: TUI в стиле Claude Code, `web_fetch` с allowlist, самохостинг.

## Тестовая стратегия

| Уровень | Инструмент | Что покрывает |
| --- | --- | --- |
| Unit | `cargo test` | Домен, парсеры, политика, бюджеты, детекторы |
| Property | `proptest` | Машина состояний, нормализация повторов, усечение контекста |
| Интеграция | mock OpenAI-сервер (`testkit`) | LLM-клиент, tool-call деградации, retry |
| Симулятор | движок + фейковые часы + инъекция падений | Полные прогоны, восстановление, детекторы |
| Golden | фикстуры журналов | Регрессии формата событий и решений |
| macOS-специфика | CI на `main` | PTY, launchd, сигналы, пути |

Порог покрытия: **80% для `core`, `llm`, `tools`**; UI-код и стабы — без порога.
Требование «тесты на всё» трактуется как: нет ветки логики без теста, нет исправленного
бага без регрессионного теста.

## Метрики v0.1 (критерии успеха)

- ≥ 3 подзадачи подряд, закрытые с зелёными гейтами, без вмешательства человека.
- 0 потерянных данных при `kill -9` в любой точке протокола.
- 0 случаев двойного применения неидемпотентного действия.
- Срабатывание детекторов: каждое зафиксировано в журнале с типом и уровнем.
- Эскалации не блокируют прогресс: при `pending` эскалации задача продолжает работу.
